# PRD: TratoBot — бот для учёта финансов «Завтра на диете»

## 1. Описание продукта

TratoBot — Telegram-бот для учёта личных финансов. Позволяет вести бюджет, отслеживать расходы, копить на цели и получать регулярные отчёты. Бот выступает в роли ироничного напарника: говорит коротко и по делу, без подхалимажа и запугивания.

### Целевая аудитория
- **Первичная:** автор и ближнее окружение (семья, друзья)
- **Вторичная:** в будущем — публичные пользователи (возможна монетизация через рекламу в Shorts)

## 2. Функциональные требования

### 2.1 Управление бюджетом
- Настройка месячного дохода
- Указание обязательных платежей (аренда, связь, подписки)
- Настройка «Кубышки» (резерв на чёрный день)
- Установка желаемой цели («Хотелка»): название + цена
- Выбор дня старта периода (1-е число, сегодня, произвольное)
- Режим округления трат: выключен / до 10₽ / до 100₽ (излишек уходит в Хотелку)
- Возможность добавить дополнительный доход в текущий период
- Возможность полного сброса бюджета и перезапуска

### 2.2 Добавление расходов
- Свободный текстовый ввод: «300 кофе» или «300 кофе\n500 обед»
- Автоматическая категоризация по ключевым словам (с самообучением)
- Ручная смена категории после добавления
- Создание собственных категорий
- Поддержка голосовых сообщений (заглушка — «бота пока нет голоса»)

### 2.3 Статус и аналитика
- Главный экран статуса:
  - Бюджет на период, дневной лимит
  - Зоны: зелёная (всё ок), синяя (можно больше), жёлтая (внимание), красная (критично)
  - Прогноз до конца периода
  - Симуляция «снять с Кубышки»
- Дневной лимит с динамическим пересчётом
- История расходов с пагинацией, редактированием, мягким удалением

### 2.4 Регулярные отчёты (по расписанию, MSK)
- **08:00 — Утренний отчёт:** статус на сегодня, зона, быстрые кнопки
- **22:00 — Вечерний teaser:** предложение добавить расходы за день
- **23:30 — Автозакрытие:** финальный отчёт за день

### 2.5 Критический сброс (Critical Reset)
При падении остатка ниже комфортного уровня:
- Зелёная зона (>500₽ свободно): предложение продолжить
- Жёлтая зона (100–500₽): предупреждение + пересчёт
- Красная зона (<100₽): полный перезапуск бюджета с ре-онбордингом

### 2.6 Самообучение категоризации
При смене категории для расхода бот запоминает ключевое слово и в следующий раз определяет его автоматически (difflib + keyword matching).

## 3. Технические требования

## 4. Архитектура и разделение на слои

```
src/
├── core/             # Конфигурация, константы
├── db/               # Модели, миграции, репозитории
│   └── repo/         # (будущее) репозитории доступа к данным
├── services/         # Бизнес-логика (не зависит от aiogram)
├── bot/              # Слой представления (Telegram)
│   ├── handlers/     # Обработчики команд и сообщений
│   ├── keyboards/    # (будущее) фабрики клавиатур
│   ├── keyboards.py  # Фабрики клавиатур
│   ├── scheduler.py  # Планировщик задач
│   └── main.py       # Точка входа
└── utils/            # Вспомогательные утилиты
```

### Жёсткое разделение
1. **Слой представления (bot/):** хендлеры, клавиатуры, FSM. Без бизнес-логики. Только вызов сервисов и работа с Telegram API.
2. **Слой бизнес-логики (services/):** сервисы. Не импортируют aiogram. Не знают о БД напрямую — только через модели.
3. **Слой доступа к данным (db/):** модели SQLAlchemy, репозитории. Без бизнес-логики и UI.
4. **Слой конфигурации (core/):** переменные окружения, общие настройки.

## 7. Definition of Done

Фича считается завершённой, если:

1. Поведение работает во всех описанных сценариях (happy path + edge cases из спецификации)
2. Ошибки обрабатываются до пользователя — никаких необработанных исключений
3. Все новые строки для пользователя вынесены в единое место (в будущем — `phrases.py`)
4. Написаны unit-тесты (pytest) для новой логики, и они проходят
5. Нет новых lint-ошибок (`ruff`)
6. Код проверен в SQLite и PostgreSQL (если менялась схема БД)
7. Соблюдено разделение слоёв: хендлеры не содержат бизнес-логики, сервисы не импортируют aiogram
8. Соблюдены naming conventions (раздел 6)

## 8. UI и стиль взаимодействия

### 8.1 Модель взаимодействия
- Всё управление — через inline-клавиатуры
- Команды: `/start` (онбординг), остальное — через кнопки
- Свободный ввод текста для расходов, чисел, названий
- Минимум шагов до цели: трата добавляется в 1 сообщение

### 8.2 Характер бота
- **Роль:** интеллектуальный напарник, ироничный, но глубоко лояльный
- **Тон:** минималистичный стендап, коротко и по делу
- **Метафоры:** добыча, фундамент, каркас, стройка, навигация
- **Правило 2 предложений:** максимум 2-3 предложения на сообщение
- **Запрещено:** «финансовый тренер», подхалимаж, угрозы, оценочные суждения
- **Обращение:** на «вы» (если не изменено пользователем)

### 8.3 Цветовые зоны
| Зона | Условие | Тон сообщения |
|------|---------|---------------|
| 🟢 Зелёная | Расходы ≤ 70% периода | Спокойный, «каркас держится» |
| 🔵 Синяя | 70-90% | «Можно и расслабиться» |
| 🟡 Жёлтая | 90-100% | Внимание, «край» |
| 🔴 Красная | >100% | Критично, предложение действий |

## 9. Будущие планы (за рамками текущей версии)

- **Умные итоги месяца:** AI-генерация сводки с комплиментами и замечаниями
- **Режим отпуска:** смена валюты, отключение ворчания на рестораны
- **Аналитика выходных vs будней:** различие в паттернах трат
- **AI-ассистент:** бот анализирует расходы и даёт инсайты, без прямого диалога с LLM
- **Голосовой ввод:** парсинг голосовых сообщений через ASR + AI

## 10. Компромиссы и ограничения

- База данных не шардирована — один инстанс на всех пользователей
- Категоризация rule-based + difflib, не AI (пока)
- Нет rate limiting (в рамках одного пользователя не актуально)
- Нет админ-панели — всё управление через Telegram
- Логирование только в stdout (лежит на Railway)
